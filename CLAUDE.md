# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kiln is a static documentation site (MkDocs + Material theme) for reverse engineering and systems programming notes — book notes, tooling cheatsheets, digital forensics course notes, and crackme writeups. Deployed to GitHub Pages at https://nafud.github.io/kiln/. It is a personal project: content is CC BY 4.0, but external contributions are not solicited — do not add contributor-facing files (CONTRIBUTING, issue/PR templates); they were deliberately removed.

## Commands

```bash
pip install -r requirements.txt   # install dependencies (or: uv venv && uv pip install -r requirements.txt)
mkdocs serve                      # local dev server at http://127.0.0.1:8000/kiln/
mkdocs build --strict             # production build into site/; fails on warnings (what CI runs)
python tests/smoke.py             # browser smoke test against site/ (build first; CI runs it too)
                                  # needs: pip install -r requirements-dev.txt && playwright install chromium
```

Dependency versions are pinned in [requirements.txt](requirements.txt). Dependabot opens weekly PRs for pip and GitHub Actions updates — review Material theme bumps on `secondary` before promoting, since theme updates can rename internal classes that [extra.css](docs/stylesheets/extra.css) and the scripts hook into (e.g. the code-copy button changed from `.md-clipboard` to `.md-code__button` across versions).

## Branch workflow and CI

Three long-lived branches form a pipeline. Work flows strictly downward — `redact` → `secondary` → `primary` — and never skips a tier:

- `redact` — writing desk. Long-lived branch where content is written gradually (draft chapters, half-finished notes). Unfinished states are first-class here: pages may be missing from `nav`, links may dangle, strict builds may fail — none of it matters because `redact` never reaches production directly and **no CI runs on it** (by design; a mid-draft red ✗ would be noise). Preview drafts locally with `mkdocs serve`. When a piece is ready, merge `redact` into `secondary`; immediately after each promotion, merge `secondary` back into `redact` so the desk stays current — skipping the sync-back is what causes `mkdocs.yml` nav conflicts later.
- `secondary` — test/integration branch, **always promotable**. Everything on it is finished work verified with a local `mkdocs serve`; every push runs [.github/workflows/build-check.yml](.github/workflows/build-check.yml) (`mkdocs build --strict` plus the theme-internals canary), so broken links and nav mistakes fail CI before they can reach production. Small self-contained changes (typo fixes, styling, config) are committed here directly; gradual content work arrives by merging `redact`.
- `primary` — production. Pushing here triggers [.github/workflows/deploy.yml](.github/workflows/deploy.yml), which builds (non-strict — validation already happened on `secondary`; the deploy build must not fail late), stamps `site/version.json` with the commit and date (what the palette's `:version` reports), and deploys to GitHub Pages; it can be re-run manually from the Actions tab (`workflow_dispatch`). Receives only fast-forward pushes of CI-verified `secondary` states, once the user confirms: `git push origin secondary:primary`. A promotion done as a GitHub PR merge instead adds a merge commit to `primary`; after one, fast-forward `secondary` (and `redact`) to the merge commit so the next promotion fast-forwards again.
- Layout/content experiments that are just "to see how it looks" go on a throwaway branch (e.g. `experiment/<name>`), deleted afterwards — not commit+revert pairs on the long-lived branches.

## Structure

- [mkdocs.yml](mkdocs.yml) — site config: theme + the palette list that defines the site's themes, light `default` first so it is the default, then dark, tokyo day, tokyo night, catppuccin latte, phosphor, terminal, nord, vesper. A theme's identity is its **scheme+primary pair**: light themes use a custom scheme name (Material's own defaults live on `:root`, so an unknown scheme inherits the stock light internals and extra.css re-colors it through the tokens alone), while dark themes all ride `scheme: slate` with a distinct `primary` slug — Material's entire dark kit (Pygments, admonitions) is scoped to slate in palette.css, so a custom-named dark scheme would render light code blocks on a dark ground. No `media:` on any entry, so nothing follows the OS "auto" preference — the site is deterministically light until the reader picks; the entries keep their `toggle:` blocks so Material renders the `__palette` radio group that the `t` key cycles and the palette's `:themes` command lists, each `toggle.name` being the theme's display name in that list, the button itself hidden by extra.css — `t` reads the scheme+primary pair applied to `<body>` to find the current theme, since Material leaves the radios unchecked on a fresh visit. Also `theme.custom_dir: overrides` (the 404 template, the terminal header partial, and the pre-paint `kiln-js` script), features (`navigation.instant`, `navigation.prune`, `navigation.footer` for key-nav.js, etc.), markdown extensions, `extra_javascript` load order, and `validation` settings. The search plugin stays although Material's search UI is hidden — quick-jump.js reads the `search_index.json` it emits. Link problems are escalated to warnings so `--strict` fails on them — including cross-page anchor fragments (`validation.links.anchors`); the homepage is intentionally not in `nav`, so `nav.omitted_files` stays at `info`. `theme.font: false` disables Material's Google-Fonts loading — JetBrains Mono is self-hosted (see extra.css) and no Google origin is contacted at all. Two `extra_javascript` order constraints: page-utils.js stays first (the shared `KilnUtils` global), and quick-jump.js precedes ascii-logo.js (their page-change hooks run in load order, so the homepage jump bar is in the DOM before the logo sizes itself against the article's remaining free height). The `nav:` section must be updated manually when adding pages or sections.
- [docs/](docs/) — all content as Markdown. Every folder (section and sub-section) has an `index.md` landing page — with a `.home-grid` card grid when it has child pages to point at, **except** writeup-collection landing pages (`writeups/crackmes-one/`), which list their solutions as a metadata Markdown table (`| Crackme | Difficulty | Quality | Arch |`) instead of cards. The top level is flat — `Guides → {radare2, volatility3}`, `Links`, `Books → book folders`, `Bookmarks`, `Courses`, `Writeups → {Crackmes.one, Challenges.re, Hack This Site}` — with no umbrella tiers above these six categories. The curated-link pages (`links/`, `bookmarks/`) render their entries as single-column `| Resource |` Markdown tables — see "Adding content". **Everything under `docs/` gets built and published** — do not put internal/non-public files here.
- [docs/index.md](docs/index.md) — homepage: the ASCII-logo `pre` (with plain-text fallback + `aria-label`), the six category cards (the **no-JS fallback** — with JS on they are hidden and quick-jump.js mounts the jump bar in their place, see that script's bullet), and an attribution line tagged `{: .home-attribution }`. It deliberately has **no `# h1`** — the logo is the title, and extra.css hides the `h1` Material generates from the page title (`.md-content__inner:has(.kiln-ascii) > h1`). The attribution link is the one external link intentionally **without** the `.external-link` icon (a chain icon would be noise in a footer signature); it still opens in a new tab like every off-site link, via external-links.js.
- [docs/stylesheets/extra.css](docs/stylesheets/extra.css) — all custom styling: the terminal frame (a fixed 1px pane border inset `--kiln-frame-inset` from the viewport edges, drawn by `body::before`, with `html::before/::after` background masks clipping scrolled content at the frame lines — every non-default theme is therefore re-declared via an `html:has(> body[data-md-color-scheme="…"])` twin so those html pseudo-elements resolve its colors too), the header and statusline label rows centered on the frame's top/bottom border lines (opaque `--color-bg` label chips, the tmux pane-title look), the hidden document scrollbar (the statusline is the position indicator), JetBrains Mono as the global font, color variables in `:root` (the light theme) re-declared per theme: the light customs as `[data-md-color-scheme="tokyo-day"]` (Tokyo Night's day variant, blue ink on a cool grey ground) and `[data-md-color-scheme="catppuccin-latte"]`, the darks as `[data-md-color-scheme="slate"]` (dark, also the base every slate-riding theme overrides) plus slate+primary pairs `[data-md-color-scheme="slate"][data-md-color-primary="…"]` for `tokyo-night`, `phosphor` (a P1 green CRT, Kiln's own — one phosphor at falling luminance for the whole ladder, a glowing shadow; Pygments keeps Material's dark colors inside code blocks deliberately), `terminal` (grey on true black, ANSI cyan accent), `nord` (the canonical Polar Night/Snow Storm ladder, frost accent), and `vesper` (near-black, peach accent) — the two-attribute pair selector outranks the base slate block, and each pair block may set `--md-hue` to tint Material's slate internals toward the theme — ASCII logo sizing variables, card grid, register cards, and the palette's `:` command output. Headings are explicitly `--color-text-primary` (Material's own h1 color variable tracks only its built-in schemes, not a custom one). Sidebars have no CSS because they have no DOM — overrides/main.html empties Material's `site_nav` block site-wide (see that bullet). The Material footer is hidden entirely (`.md-footer { display: none }`) — its prev/next links still feed key-nav.js. Notes:
    - Card rules are scoped as `.md-typeset a.home-card` — a bare `.home-card` selector loses the cascade to Material's generic `.md-typeset a` rule (transitions get replaced and cards dim on hover).
    - The first paragraph after a page's `h1` renders as a faint subtitle (`h1 + p` rule) — every page's intro line relies on this, except book chapters (the TL;DR admonition follows the h1, so the rule never matches) and ledes tagged `.plain-intro`, which the adjacent override renders as normal body text.
    - The "Copied to clipboard" dialog is intentionally suppressed via `[data-md-component="dialog"] { display: none }`; code-copy itself still works.
    - Fonts are fully self-hosted, no Google Fonts anywhere: JetBrains Mono's four weights live in `docs/assets/fonts/` (official woff2s, OFL license file alongside — keep it, it ships with the font) behind the `@font-face` rules at the top of this file, with the Regular weight preloaded from overrides/main.html; the logo font is embedded in ascii-logo.js.
    - The palette's results dropdown carries `overscroll-behavior: contain`, so a wheel gesture that runs it to its end never chains into scrolling the main page.
    - Material's header search bar and palette toggle are hidden (`.md-search`, `[data-md-component="palette"]`) — `` ` `` summons the jump palette and `t` cycles the color scheme instead; the search plugin still runs for the palette's index.
    - External links out of the site are marked with `.external-link` (a trailing chain-link SVG-mask icon, tinted via `currentColor` so it matches the link color and hover) applied via `attr_list`: `[text](url){ .external-link }`. The icon applies to **all** external links in content, not just the curated-link tables; the homepage attribution is the sole deliberate exception. Do **not** add `target=_blank rel=noopener` per link — external-links.js does that automatically for every off-site anchor.
    - Homepage-only rules are gated on `:has(.kiln-ascii)` (no homepage-specific class exists): they hide Material's generated `h1` and flex-stretch the `.md-main → .md-main__inner → .md-content → .md-content__inner` chain so the attribution's `margin-top: auto` pins it to the bottom of the viewport. `.md-main__inner` is pinned to `width: 100%` in that chain — as a flex item of the column-flexed `.md-main`, the auto-margined `.md-grid` otherwise shrink-wraps, and with no sidebars in flow the whole column (and the ASCII logo generated into it) collapses to text width.
- [docs/javascripts/page-utils.js](docs/javascripts/page-utils.js) — shared `KilnUtils` global: `debounce`, `onPageChange(fn)` which runs `fn` on load and after every `navigation.instant` page change (via Material's `document$`, falling back to `DOMContentLoaded`), and `twosReadout(value, width)` — the two's-complement readout shared by the CSAPP widget and the palette's `:x -wN` mode, deliberately written without BigInt literals so an old parser fails only where BigInt is exercised, not on this file. Must stay **first** in `extra_javascript`; the other scripts depend on it.
- [docs/javascripts/external-links.js](docs/javascripts/external-links.js) — stamps `target="_blank"` + `rel="noopener"` on every anchor pointing at another origin (content links and the header repo link alike), so off-site links open in a new tab by default and Markdown never carries per-link `target=` attributes. Anchors with an explicit `target` keep it. Re-runs via `KilnUtils.onPageChange`; progressive enhancement — with JS off, links still work, just in the same tab.
- [docs/javascripts/page-chrome.js](docs/javascripts/page-chrome.js) — the statusline (`.kiln-status`, always present on the frame's bottom border) and the header nav's active marker. Left segment: the page path below the site root, `~`-prefixed (`~/books/csapp/csapp-chapter-03`; plain `~` on the homepage), derived from `location` against the header logo's href (the same site-base derivation quick-jump.js uses). Right segment: the position token — `All` when the page fits, `Top` at the start, otherwise the percentage (held to 99% until the bottom is actually reached, where it reads `100%`). The scroll range is cached (measured on init/resize/page change, re-synced after each scroll burst), so the per-scroll-event path never reads `scrollHeight` — that read forces a layout flush per frame during wheel scrolling. `syncActiveNav` restamps `kiln-header__link--active` per page change (a section is active for every page under its directory; on the homepage no item is): the header is rendered once per full load and `navigation.instant` never re-renders it, so the Jinja-stamped active class would go stale. Init is idempotent and re-runs via `KilnUtils.onPageChange` because `navigation.instant` removes injected DOM on navigation.
- [docs/javascripts/key-nav.js](docs/javascripts/key-nav.js) — keyboard navigation, with the scroll motions case-accurate vim: `gg` (two-tap chord) / `G` jump to top/bottom, lowercase `j`/`k` step down/up (uppercase forms deliberately dead — vim means other things by them), `[`/`]` jump to the previous/next `h2` section (anchor line just below the top chrome), `<`/`>` follow the previous/next page in nav order, `0` goes home (clicks the header `md-logo` link), `1`–`6` open the top-level categories (clicks the header nav links from overrides/partials/header.html — the nav lists exactly the six sections, home being the `[kiln]` wordmark and the `0` key), `t` cycles the color theme (advances Material's `__palette` radio group in mkdocs.yml order; the header toggle button is hidden, and the palette's `:themes` command lists the same radios by name). There are no sidebars and no toggle for them — the header nav is the navigation and the palette's `:toc` lists the page's headings — and there is no help binding — help is the palette's `:h`/`:help` usage output (see quick-jump.js, which owns the binding table those commands print; keep it in sync when bindings change). All letter bindings are strictly lowercase (uppercase forms are inert, as in vim). Page switching clicks Material's footer prev/next links (`md-footer__link--prev/next`), which exist in the DOM only because `navigation.footer` is enabled in mkdocs.yml — the footer itself stays `display: none`; the click path keeps `navigation.instant` in charge. Keys are inert while typing and in Ctrl/Alt/Meta chords; Material's search keys `s`/`S`/`F`/`/` **and** its `p`/`n` page keys are all neutralized by a capture-phase listener, so nothing summons the hidden search form and no second page-motion vocabulary competes with `<`/`>` — all of them are plain dead keys there (a bubble-phase swallow would lose the race to Material's earlier-registered handler), `n`/`N` belong to the palette's `/` search as vim's search-repeat motions (quick-jump.js owns them; its capture listener registers earlier, so it wins the race while a search is armed, and otherwise they fall through to the swallow as dead keys), `p`/`P` dead as well (vim means paste by them), and the palette belongs to `` ` `` alone (all still type in inputs); scrolling is smooth unless `prefers-reduced-motion`. Attach-once (no per-page init).
- [docs/javascripts/quick-jump.js](docs/javascripts/quick-jump.js) — jump-to-page palette, the site's navigation and its search (Material's search UI is hidden; the search plugin only feeds this). `` ` `` or Ctrl/Cmd+K summons the prompt — the homepage's inline bar when mounted, an overlay elsewhere: a typed query searches everything — pages fuzzy-matched by title and path rank first (substring hits outrank subsequence scatter; whitespace-separated terms must all match, so `csapp 3` works), then section-content hits fill the remaining rows as `page › section` rows (literal substrings only in body text, deduped and capped at two rows per page; the title is the row's whole content, no excerpt column), so a term living only in body text (`memcmp`, `0x5A`) surfaces without any prefix — ArrowDown/ArrowUp select, Enter clicks the result's real link (keeping `navigation.instant` in charge), Escape or a backdrop click closes; the prompt rests as a bar showing a `█` terminal cursor (steady while unfocused, blinking while focused, the Linux console convention) plus a faint `type :h for help` placeholder (the block cursor hides and the native caret takes over at the first typed character, driven by `:placeholder-shown`; an empty query still shows no results), and the current page is never offered. A leading `:` is vim command-line mode, parsed exactly before page search ever runs (so a colon-prefixed query can never collide with content): `:h`/`:help` print the keyboard-binding and command table (`.kiln-jump-help`, one non-selectable `pre` grouped into `[ NAVIGATION ]`/`[ SEARCH ]`/`[ VIEW ]`/`[ COMMANDS ]` sections from the script's `HELP_SECTIONS`, descriptions aligned to one site-wide key column) — this is the site's help, its only trigger, the former bottom-right panel and hint being gone; `:version` prints the deployed build stamp (fetched lazily from `version.json`, written by deploy.yml — absent on any local serve, where it reports `local build`); `:intro` prints a centered welcome screen (spaced `KILN` title, the attribution line, the six top-level sections as a `[0x01]`–`[0x06]` grid whose labels are the `1`–`6` keys that open them, and the live page count from the index); `:x expr` is the integer calculator — a hand-rolled recursive-descent parser over BigInt (never `eval`), C operators at C precedence with `0x`/`0b`/`0d`/decimal literals, answering in hex/dec/bin, evaluated live per keystroke; a leading `-wN` flag on it (`:x -w16 expr`, widths 8/16/32/64) switches the answer to the two's-complement readout at N bits (bits/hex/unsigned/signed, `KilnUtils.twosReadout` — the same function the CSAPP widget renders); command-line errors (`E471` missing expression, `E475` bad width, `E15` rejected expression, `E492` unknown command) render as single message rows in the `no matches` style — the row-metric `.kiln-jump-empty` element, never the output `pre`, so an error cannot render at a different size than the rows (vim shows errors in the message line, not as buffer output); `:toc` lists the current page's `h2`/`h3` headings as jumpable rows (h3s indented via `.kiln-jump-result--sub`) — same-page anchor rows (from `:toc` or a section hit on the open page) dismiss the prompt on Enter themselves, since no page change will; `:themes` lists the color themes as selectable rows read from Material's `__palette` radios (mkdocs.yml is the single source of truth — each row is a radio's `toggle.name`, the current theme carries a trailing `*` identified by the scheme+primary pair since the dark themes all share scheme slate, and Enter or a click applies the theme by clicking its radio, Material persisting the choice, then dismisses the prompt; these are action rows, href-less anchors whose callback the delegated click funnel runs); any other `:name` answers `E492: Not an editor command: name` (as does a trailing argument on a command that takes none), and a bare `:` does nothing, as in vim. A leading `/` is vim's buffer search over the whole site: `/pattern` (two-plus characters) greps section headings and body text case-insensitively — including each page's pre-heading text (intro paragraphs, TL;DR admonitions, metadata blocks), which the search index stores on the page-level entry and joins the section list as an "intro" section landing on the page itself — returning selectable `page › section` rows (the page title alone for intro rows) that land on the section anchor. Opening a `/` result (Enter or mouse alike — both funnel through one delegated click listener) arms vim's `hlsearch` on the landing page: every literal match tints via the CSS Custom Highlight API (`::highlight(kiln-search)`/`-current` in extra.css — no DOM mutation, so heading-shimmer and instant navigation never collide with it; browsers without the API keep the motions minus the tint), `n`/`N` cycle the matches (the first press seeks from the header anchor line, then they step and wrap) and `Escape` outside the palette clears the search. The armed pattern rides to the landing page in sessionStorage (module state would die on a full-load navigation — `navigation.instant` only intercepts links matching the page's configured base, so static serves navigate cold); modified clicks (new tab) never arm it; ranges rebuild per page and are capped at 500. The dialect is vim-only — the former GNU `-h`/`--help` flags are gone. All search data comes from the search plugin's `search_index.json` (one page-level entry per page plus one entry per heading section), fetched once per full page load — prefetched on browser idle so the first keystroke never waits, with the on-demand load as fallback — no extra build step; the site base is derived from the header logo's href. The input carries the combobox ARIA pattern (`aria-activedescendant` traversal plus a visually hidden `aria-live` result count, `.kiln-jump-status`). The same component **always mounts inline under the homepage ASCII logo**, input focused, so the homepage is a prompt; its results float as a dropdown over the content below the bar (clamped to the viewport), so matches never change the page height. Because the inline bar is always visible, its dismissal (Escape, an action row like `:themes`, a same-page anchor row, or a click anywhere outside the bar — the counterpart of the overlay's backdrop click, attach-once on the document) resets it to the resting prompt, query cleared and dropdown gone; no page change would clear it otherwise. The homepage card grid in the Markdown is the no-JS fallback: [overrides/main.html](overrides/main.html) stamps `kiln-js` on the html element before first paint and extra.css hides the cards under it (scoped by the ASCII-logo gate — category landing pages keep their card grids); with JS off the class is never set and the cards render as always. The overlay lives on `document.body` (attach-once); the inline variant re-mounts per homepage visit via `KilnUtils.onPageChange`.
- [docs/javascripts/widgets.js](docs/javascripts/widgets.js) — **experimental** interactive content widgets, pure vanilla JS. Progressive enhancement: a page drops an empty `<div class="kiln-widget" data-widget="NAME">` after the block it animates, and this hydrates it by `data-widget` type; with JS off the div is empty and the surrounding prose and code stand alone. Mounting is idempotent, lazy (no-op on widget-less pages), re-run via `KilnUtils.onPageChange`, and marks each node `data-mounted` so a re-run never double-hydrates. Two widgets so far, both built on the shared terminal-prompt scaffold (`createTerm`): `cfb1-keygen` on the CFB1 writeup — type a username, see the serial computed live by that page's verified derivation (so the widget and the prose must stay in step) — and `twos-complement` on CSAPP chapter 3 §3.5.4: one integer literal (dec/`0x`/`0b`/`0d`, BigInt-exact) read at a chosen width (the `-wN` flag is a real button cycling 8/16/32/64) as raw bits, hex, unsigned, and signed — the passage's same-bits-two-readings point made interactive, rendered by the shared `KilnUtils.twosReadout`. Widget CSS uses the design tokens and the surface recipe, so it follows the theme; no Material `md-*` internals are hooked, so the build-check canary is unaffected. Loaded last in `extra_javascript`.
- [docs/javascripts/code-copy.js](docs/javascripts/code-copy.js) — swaps the code-copy button icon to a checkmark after a copy (one delegated click listener; no per-navigation init). Material's own copy feedback is the toast dialog that extra.css hides; the checkmark is a CSS swap of the button's `::after` mask via the `md-code__button--copied` class. The restore is staged: `--leaving` fades the check out, then `--restoring` animates the copy icon back in. Swap timing is single-sourced from `--kiln-icon-swap-duration` in extra.css (the script reads it at runtime).
- [docs/javascripts/ascii-logo.js](docs/javascripts/ascii-logo.js) — generative homepage ASCII logo. Renders `CONFIG.text` ("Kiln") in UnifrakturMaguntia on an offscreen canvas, samples glyph coverage per character cell, and maps it through a contrast curve (background below `coverageFloor`, solid ink above `coverageCeil`, a short gradient between) onto a deliberately short density ramp inside `pre.kiln-ascii` — a long ramp turned anti-aliased edges into mid-density mush and near-zero coverage into background speckle. Sized to fit the content width and a height budget that is the viewport ratio cap tightened by the article's real free height, read from the pinned attribution's `margin-top: auto` used value (the column slack), so a short window never grows a scrollbar. Static until the cursor moves; pointer movement drives a shimmer whose intensity envelope eases in/out. The two ramps split the two jobs: the short `charRamp` renders the crisp static frame, and animated frames displace ink cells along the long `glitchRamp` (the rich alphabet is what makes the shimmer read as terminal noise — on the short ramp the same fractional swing collapses to a couple of steps and the effect goes dull); a cell displaced by less than one step keeps its exact static glyph, so the effect settles seamlessly. A page's first generated frame enters through the same machinery at full envelope, so the logo materializes out of glitch noise instead of snapping in from the text fallback; resize and self-heal rebuilds repaint statically. Key facts:
    - All tunables live in the `CONFIG` object; grid resolution is `--kiln-logo-font-size` in extra.css.
    - The grid is generated **exclusively from the verified UnifrakturMaguntia** — never from a fallback font, whose metrics would produce a wrong-looking logo that sticks. The font is a ~1.8 KB woff2 **subset to `CONFIG.text`'s four glyphs, embedded in the script as a data: URI** (`CONFIG.fontDataUrl`; the regeneration command lives in the comment above it, and the OFL copyright/license name records are retained inside the file) and registered through the FontFace API — no network fetch stands between first paint and the build, there is no `<link>` for `navigation.instant`'s head reconciliation to strip (the face persists for the document's life), and offline `mkdocs serve` renders the real grid. `ensureLogoFont` still confirms the canvas really shapes the text with it (`logoFontRendered` compares text metrics against the bare fallback — privacy modes that standardize canvas fonts report loaded faces but draw a generic font, and they keep the styled text fallback instead of getting a wrong grid); a failed check is re-run on later triggers (the `loadingdone` listener, a page revisit), so a late success still builds.
    - Waits for `document.fonts.ready` before measuring (the grid is sized from the pre's rendered JetBrains Mono cell) and rebuilds on late font loads, on window resize, and on container resize (a `ResizeObserver` on the pre's parent — late layout shifts can change the content width with no window resize, and a stale grid overflows the narrowed column).
    - Before generation the pre holds its plain-text fallback styled as a title, but JS visitors never see it flash: under the pre-paint `kiln-js` class extra.css keeps the not-yet-generated pre invisible and the grid materializes into the blank, while a pure-CSS delayed fade-in (~2s) reveals the title anyway if generation never comes (script blocked, canvas privacy mode) — no JS failure path involved. With JS off the title renders immediately, as before. The `kiln-ascii--generated` class switches the pre to grid sizing.
    - To change the word: `CONFIG.text` **plus** the fallback text/`aria-label` in [docs/index.md](docs/index.md) **plus** a regenerated `CONFIG.fontDataUrl` — the embedded subset holds only the current word's glyphs. To change the font: `CONFIG.fontFamily` and a `CONFIG.fontDataUrl` subset of the new font.
- [docs/javascripts/heading-shimmer.js](docs/javascripts/heading-shimmer.js) — hover shimmer for page `h1`s, the logo effect's interactive cousin: hovering the heading text scrambles its letters and digits along the logo's density ramp (same motion constants), sustains while hovered, and settles back to the exact original text after leave. The hover target is an injected inline wrapper (`.kiln-shimmer-target`), so the h1 block's empty width doesn't trigger. Substitutions are **alphanumeric-only** and every other character is a fixed point — punctuation like `-`/`/` creates soft-wrap opportunities, and changing those mid-shimmer rewraps multi-line titles and reflows the page. Respects `prefers-reduced-motion`; idempotent across `navigation.instant`.

## File naming convention

Each folder's landing page stays named `index.md` (this keeps clean directory URLs like `/books/csapp/` and drives Material's `navigation.indexes` feature; the homepage `docs/index.md` must also keep this name). Every **non-index content page is prefixed with its folder's slug** so filenames are globally unique and greppable — e.g. `books/csapp/csapp-chapter-07.md`, `books/pba/pba-chapter-01.md`, `writeups/crackmes-one/crackmes-one-cfb1.md`. Folder slugs are short codes: `mx86alp` (Modern x86 ALP), `ild`/`ime`/`iwe`/`iwm` (the Investigating … courses).

Tool guides are an exception to the prefix rule: each guide is its **own folder** whose entire content lives in its `index.md` (e.g. `guides/radare2/index.md`), giving it a clean URL (`/guides/radare2/`) and room to grow sub-pages later.

**Page heading + subtitle convention.** Every content page opens with a single `# h1`, immediately followed by one intro paragraph — extra.css's `h1 + p` rule renders that paragraph as the faint subtitle, so it must be prose, not a list or table. **Two exceptions**: book chapters carry no subtitle paragraph — the TL;DR admonition follows the h1 directly (a subtitle would only restate it; see "TL;DR" under Writing style) — and a lede tagged `{: .plain-intro }` (the radare2 guide) renders as normal body text instead of the faint subtitle. Book-chapter h1s use the uniform house style **`# Chapter N. Title`** (period after the number, e.g. `# Chapter 8. Exceptional Control Flow`) — match it when adding or replacing a chapter; incoming drafts sometimes arrive with an em-dash or a `Book — Chapter N:` prefix, normalize them. Pages must **not** carry YAML frontmatter — no page uses it; Material derives the `<title>` (`"<h1> - Kiln"`) from the h1, auto-generates `<link rel="canonical">` from `site_url`, and the page description falls back to `site_description`. (A `title:`/`canonical:`/`meta-description:` block on an incoming draft is redundant or non-functional here — strip it.)

## Writing style

Every page under `docs/` is a note from one reverse engineer to another. Two things matter most, in this order: technical accuracy and coherence. Clarity and concision serve them and never override them, so a sentence is never trimmed or smoothed at the cost of a fact. The register is textbook, not blog. Written for a competent peer who wants the result without being exhausted by it: clear, on point, dry, and easy to read from the first line to the last. This holds site-wide (book notes, tool guides, course notes, writeups), not only in writeups. For CSS and design rules see "Styling conventions".

**Voice.** Assume a competent peer. State findings, do not narrate the journey and do not teach down. No hype, no rhetorical questions, no self-congratulation ("as we can clearly see"), no tour guiding ("let's dive in", "now we will"). Prefer impersonal statements over second person. Say a thing once.

**Flow.** The prose reads as one continuous line of reasoning. Each sentence follows from the one before it, and each paragraph hands off cleanly to the next, so there are no abrupt jumps and no clunky seams. When a step depends on a fact established earlier, carry that fact forward in words rather than assuming the reader reassembles it. Concision means cutting what carries no information, not compressing what remains into fragments, arrow chains, or shorthand. A shorter note the reader has to decode twice is not shorter. Read a finished page top to bottom once; if a transition jars or a sentence lands without a reason to be there, fix it.

**No fillers.** Cut `simply`, `just`, `obviously`, `of course`, `basically`, `note that`, `it is worth noting`, `as we know`. `in order to` becomes `to`. Delete any sentence that only announces the next one. A clause carrying no fact is cut.

**Punctuation.** Two hard bans, both in prose only.

- No em dashes (`—`) and no double hyphens (`--`). Recast with a comma, parentheses, or a second sentence.
- No colons, including in a caption that introduces a code block. A bold lead-in label ends with a period (`**Storage.**`, `**In one line.**`), never a colon.
- Both bans leave content alone. Hyphens inside tokens stay (`x86-64`, `PE32+`, `case-sensitive`, `2-digit`), and so do colons inside code spans, code blocks, URLs, table syntax, and the metadata-block labels described below.

**Accuracy.** Nothing is asserted that was not checked.

- Every address, instruction, constant, offset, hash, and console line is verified against the actual file or an actual tool run. Never reconstruct output from memory or from expectation.
- A command shown must reproduce the output shown. When output is filtered for readability, show the filter (`strings -n 6 CFB1.exe | grep -E '\[[-+*]\]'`) instead of silently trimming a raw dump.
- Do not imply a tool was run when it was not, or that a binary was executed when the work was static.
- Justify an identification rather than naming it. `0x1400297a0` is `memcmp` because it takes two pointers and a length and returns zero only on full equality.
- Effects before encodings. "Each byte prints as two uppercase hex digits" first, the flag bits that cause it second.
- State assumptions in place (ASCII input, byte-wide wrap).
- Scripts are complete and runnable, with a filename, an invocation, and their real output. No fragment that errors when pasted.

**Reproducibility.** A reader holding the same file and the note must reach the same result. Derive a constant before using it (`delta(.rdata) = vaddr - paddr`), then apply it. Prefer the mechanical path a reader can repeat over a shortcut that only worked because the author already knew the answer.

**TL;DR.** A book chapter opens with a `!!! tip "TL;DR"` admonition immediately after the `# h1` (no subtitle paragraph). It is one dense, well-written paragraph carrying the chapter's load-bearing facts, so a reader gets the whole result before the detail and can decide what to read closely. Any orienting fact worth keeping (target toolchain, scope) is at most a short paragraph after the TL;DR; a general intro that carries no technical fact is cut. A chapter has **no Summary section** — the TL;DR is the summary, and a closing recap that adds nothing new is cut. [csapp-chapter-03.md](docs/books/csapp/csapp-chapter-03.md) is the reference. Writeups carry their own TL;DR holding the answer (formula or key) rather than a chapter summary; see the writeup skeleton.

### Writeup skeleton

[crackmes-one-cfb1.md](docs/writeups/crackmes-one/crackmes-one-cfb1.md) and [crackmes-one-cfb2.md](docs/writeups/crackmes-one/crackmes-one-cfb2.md) are the reference implementations. The order is fixed.

1. `# h1`, the challenge name alone (`# CFB1`), no subtitle in the title.
2. Metadata block, a single paragraph of bold label and value lines joined by Markdown hard breaks (two trailing spaces), ordered Source (link to the challenge), Author, Difficulty, Quality, Language, Platform, Arch. It is the `h1 + p` paragraph, so extra.css renders it as the faint grey block. Keep it a paragraph; a table here loses the styling.
3. Intro prose, one paragraph, stating what the challenge is and what solving it takes. Each writeup stands alone and never cross-references a sibling challenge.
4. Info table, exactly `Target` (executable name only), `Image base`, `SHA-256`, and `Method` (`Static analysis. No debugger.`). No Toolchain or Tools-used rows.
5. `!!! tip "TL;DR"`, titled exactly `TL;DR`, holding the answer (formula or key) and a link to the section carrying the full script.
6. Numbered sections forming the reproducible spine. Triage, Strings, Locating main, Reading main, the challenge-specific routine, then the keygen or solver.
7. `## Appendix`, titled exactly that, an address table of the landmarks used.

There is no Summary section. The high-level statement is item 3, and the answer is item 5.

**Tool tabs.** Where a step has two tool paths, use `pymdownx.tabbed` with Radare2 first so it is the default tab, then Objdump, as `=== "Radare2"` and `=== "Objdump"` with bodies indented four spaces. Radare2 is the primary workflow and objdump is the no-frills fallback. Both bodies carry real output from that tool.

### Exercise notes

[challenges-re-re4b-ch01.md](docs/writeups/challenges-re/challenges-re-re4b-ch01.md) is the reference. Per exercise, an `## h2` carrying the number and topic, a metadata paragraph (Source link, Tags), the listing copied verbatim from the source, analysis prose, an `**In one line.**` answer, and a `**C.**` block where a C equivalent exists. Answer the questions the challenge actually asks. Where it asks three, answer three, and do not force a C equivalent onto code whose behavior is undefined.

1. Create `docs/<section>/index.md`
2. Add the section to `nav:` in [mkdocs.yml](mkdocs.yml)

1. Create the file, prefixed with the folder slug
2. Add it under the section in `nav:` in [mkdocs.yml](mkdocs.yml)

```html
<span class="home-card-text">One-line description.</span>
</a>
```

```markdown

```

(`.external-link` is only the icon — new-tab behavior is automatic via external-links.js.)

## Links (internal cross-references and external redirection)

Two link kinds, two rules — get them right or `--strict` / navigation breaks:

- **Internal links (page → page within the site)** are **relative Markdown links to the target `.md` file**, resolved and validated by `--strict`: `[CSAPP §3.6.3](csapp-chapter-03.md)` (same folder), `[Chapter 1](../../books/re4b/re4b-chapter-01.md#152-x86-64)` (across sections, with a heading anchor). MkDocs rewrites these to the final directory URLs at build. **Never** hardcode an absolute `https://nafud.github.io/kiln/...` URL for internal targets — it skips link validation and 404s against the local `mkdocs serve`. Anchors are Material's slugified headings (lowercase, spaces→`-`, dots dropped: `### 1.5.2 x86-64` → `#152-x86-64`); `validation.links.anchors: warn` makes `--strict` fail on a cross-page `#fragment` that matches no heading, so a renamed heading breaks CI instead of silently landing readers at the top of the target page. The RE4B ↔ challenges.re pair (see "Content sections") is the worked example.
- **External links (page → another origin)** are plain Markdown links tagged with the icon class: `[name](https://example.com/){ .external-link }`. New-tab **redirection is automatic** — [external-links.js](docs/javascripts/external-links.js) stamps `target="_blank" rel="noopener"` on every off-site anchor at load and after each `navigation.instant` change, so you do **not** write `target=_blank rel=noopener` per link. `.external-link` adds only the trailing chain-link icon; omit it (as the homepage attribution does) when the icon would be noise, and the link still opens in a new tab. Internal links are never redirected (external-links.js checks `origin`), so they stay in-tab.

## Styling conventions

The design language in [extra.css](docs/stylesheets/extra.css) is settled. These invariants hold across the whole site — follow them when adding styles or styled content; do not introduce parallel systems:

- **Colors come from the tokens, never hardcoded.** Every color is one of the `--color-*` custom properties defined in `:root` (the light theme) and re-declared per theme (each block with its `html:has` twin; see the extra.css bullet for the roster) — a raw hex value in a rule breaks the other themes, and a new theme is exactly one such token block plus a palette entry in mkdocs.yml (dark themes ride `scheme: slate` with a distinct `primary`, light themes take a custom scheme name — see the mkdocs.yml bullet). The text ladder runs `--color-text-primary` (headings, card titles) → `-secondary` (body prose) → `-muted` (supporting text, nav links) → `-faint` (labels, subtitles, decorative); pick the step that matches the text's importance. **The accent belongs to the theme**, declared in its token block and bridged into Material via `--md-accent-fg-color` — light/dark/tokyo day share the house blue `#2563eb`, tokyo night carries `#7aa2f7`, catppuccin latte `#1e66f5`, phosphor `#66ff66`, terminal `#00cdcd`, nord `#88c0d0`, vesper `#ffc799` — and every accent surface (links, hover lifts, hlsearch tints, the external-link icon) follows the token, never a fixed blue.
- **One typeface.** JetBrains Mono is the only font for text and code alike, self-hosted at weights 400–700 (`docs/assets/fonts/` + the `@font-face` rules at the top of extra.css, Regular preloaded from overrides/main.html) and forced (`!important`) across Material's components. Code blocks additionally disable ligatures (`font-variant-ligatures: none`) so `->` and `=>` render as typed. The sole other font is the logo's UnifrakturMaguntia, embedded in ascii-logo.js as a subset data: URI and used on the homepage only.
- **Type scale.** Content prose 0.78rem/1.7; code blocks 0.72rem/1.55; `h1` 1.8rem with a bottom border (the only ruled heading), `h2` 1.2rem, `h3` 0.95rem; the `h1 + p` subtitle 0.76rem in faint. The recurring **label style** — 0.65rem, letter-spacing, weight 700, faint/muted color, uppercase where it labels content (table header rows), lowercase on the frame chrome (header nav, statusline) — is the treatment for anything label-like; reuse it rather than inventing a new one.
- **Surface recipe.** Every raised element — home cards, register cards, code `pre` blocks, the inline jump palette — is the same construction: `--color-surface` background, 1px `--color-border` border, 4px border-radius (3px for inline code), and **flat at rest** (no box-shadow until hover). The deliberate exceptions are the layers that float over content — the jump-palette overlay panel and the inline palette's results dropdown — which carry a resting shadow for separation. The frame chrome is a second, distinct construction: the terminal pane (the fixed frame border) is a 1px `--color-border` box on the `--color-bg` ground with its labels as opaque `--color-bg` chips sitting on the border line — never a surface, never shadowed. Backgrounds elsewhere are `--color-bg`.
- **Hover grammar.** Inline links fade (`opacity: 0.75`); interactive *surfaces* lift instead: border turns `--color-accent`, `translateY(-1px)` (buttons) or `-2px` (cards), and a `--color-shadow` box-shadow appears, with inner text sharpening one ladder step (card title → accent, card text muted → secondary). All transitions are 150–200ms `ease`. Block-level links must cancel the generic link fade with `opacity: 1` on hover (see the `.home-card` cascade note above), or the whole surface dims.
- **Beating Material's cascade.** Overrides of theme internals routinely need `.md-typeset`-scoped selectors or `!important` to win — that usage is deliberate, not cruft. When a new rule hooks a Material `md-*` internal class, add it to the canary list in [build-check.yml](.github/workflows/build-check.yml).
- **Dual-context components own their typography.** The jump palette renders both inside `.md-typeset` (homepage bar) and on `document.body` (overlay), where inherited metrics differ (body's base is 10px). `.kiln-jump-panel` is therefore the palette's own typography root (family/size/line-height); every palette element inherits it or sets explicit metrics, command-line errors render as row-metric message rows rather than through the output `pre`, and the smoke test asserts computed equality of every palette element across the two contexts. Any new element mounted on `document.body` must set its type explicitly (the progress chip does), and any new palette element must stay under the root or join the smoke probe's selector list.
- Fixed chrome decisions, not to be reverted casually: the terminal frame around every page, with the header nav on its top line and the statusline on its bottom line; content column capped at 900px; sidebars removed entirely at the template level (overrides/main.html — the header nav and the `1`–`6` keys are the navigation, the palette's `:toc` the in-page orientation); the document scrollbar hidden (the statusline is the position indicator) while scrolling itself stays native and smooth; content tables full-width with `table-layout: fixed` and a label-style header row; Material footer hidden; "Copied to clipboard" dialog suppressed (checkmark feedback instead); scroll-to-top/bottom buttons replaced by keyboard navigation (key-nav.js); the homepage is the jump bar (quick-jump.js), with the Markdown card grid kept solely as the no-JS fallback — both paths must keep working.
